# Original fixed installation evidence

`LoadInstallation(directory, verifiedKit, expectedBase, expectedOwnershipJSON)` is a read-only loader for the current Python installer's complete evidence directory. It returns `(*Installation, error)` only when every local binding and original receipt is coherent. It does not run a saved command, call a target, modify files, retry a mutation, resume an installation, or return a scenario result.

Transfer the entire private original directory, including `kit/`, from the controlled installation host to the CorrTest host through an operator-trusted channel. A completion file or manually supplied IDs are insufficient. Supply the separately trusted Kit pin and explicit expected declaration/target. The exact recorded base is either the root origin or `/ext/mw`; no other path, trailing slash, query, fragment, encoded path or userinfo is accepted. This parser does not authorize plain HTTP; that remains an explicit owned-lab configuration prerequisite for callers.

The loader opens the original root and `kit/` by retained no-follow directory descriptors, reads only the fixed relative names, and rejects symlinks, special files and extra entries. Directories require 0700, files 0600, with special mode bits refused. Each actual read is limited to 1 MiB; the JSON snapshot is limited to 32 MiB and the ten copied kit files to 10 MiB. There are at most 160 operations and 323 immediate entries. Linux/macOS implement these guarantees; other platforms return the existing unsupported-platform error while preserving CLI compilation. Trusted stable parent directories and a privately stable evidence tree remain prerequisites: bounded name rechecks do not create an atomic snapshot against hostile writers.

All parsing and hashes use the captured bytes. Exact producer control schemas, UUID4 IDs, integer types and bounds, the ordered journal image hash, full copied kit bytes, original project-install operation, created-only Mapping load/rule import, and original final full authored rule/Mapping/runtime readbacks are checked. The finite emitted grammar includes pre-install and pre-import inventories and 1–120 contiguous load polls. Unsupported or interrupted records return a nil result and an error. A `failed.json`, missing after record, extra operation or changed completion never becomes a new installation.

`Binding()` exposes only copied scalar original IDs/hashes/runtime values. `Files()` and `Evidence(name)` return copied snapshot bindings/bytes; unknown names never read the filesystem. `TargetOrigin` deliberately stores the entire configured base, including `/ext/mw`. The original runtime's sole loaded rule is `RuleID`; both authoritative and dispatch flags were false. The later runtime may convert those facts into `oscar.InstalledPackBinding`, then perform the existing six fresh GETs. No such runner/CLI or SQLite integration is implemented here.

The Python journal retains the original HTTP response byte count/hash and a parsed JSON body, **not the raw response bytes**. The loader validates hash syntax/size and the parsed response semantics; it cannot recompute that raw-wire hash. It recomputes the separate journal-file hash from the retained exact records. Neither hash authenticates the operator or server. Whole-tree fabrication, change/use/restore between observations, runtime process replacement, and target exclusion cannot be disproved by these records. Ownership remains operator-declared (`ownership_observed:false`), and the expected receiver revision still requires input If-Match and acknowledgement checks.

The fixture's real Python producer and verification provenance are under `testdata/installation/`. Go controls include cross-record tampering even after rehash, private descriptor bounds, current six-GET reader composition, missing-original refusal before HTTP, and live runtime drift refusal. Controlled host peers are not deployed authentication, service readiness, scenario PASS or cleanup proof. Continuous owned-target exclusion, controlled notification destinations, and eventual DIRTY source teardown remain external requirements.

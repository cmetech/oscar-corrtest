# Ordinary initial-Flood offline test kit, v0.1.0

This is the offline artifact prerequisite for an installable correlation test kit. It has no installer, CorrTest installed-rule runner, or deployed qualification yet. Build from the matching backend feature checkout with its installed Python dependencies:

```
python3 test-packs/build_operational.py --backend ../oscar --output /tmp/correlation-operational-v1
python3 -m pytest -q test-packs/test_operational_pack.py
```

Output must be a new directory. The builder snapshots exactly five bounded authored files into a private directory before validation and uses that same snapshot for every validator, pack writer and emitted source artifact. Later edits to the authored files cannot change this build. Backend code and installed Python dependencies are a separate trusted, immutable build prerequisite; do not modify that checkout while building. This POSIX builder uses descriptor-bound regular-file reads capped at 1 MiB. The real project-pack builder emits the normal schema-1 configuration archive and sidecar. The real receiver compiler/executor validates the profile; the real complete-rule validator and portability serializer produce the normal import ZIP. No service, database, credential, network endpoint, mocked validator, or runtime capability is supplied. Validation uses reference OSCAR 26.3.0 and clean environment/default settings; the broad declared version range is format compatibility, not qualification of every release. Imported backend Python source hashes are retained. Installed dependencies and backend sources must be available locally; no downloads occur.

The fixed rule matches only exact `CorrTestOperationalFlood`. The current authoritative validator refuses enabled legacy label predicates without durable episode policy. Thus `qualification_pack` is identification, not a matching/admission security boundary. The future installer/run must require an exclusive owned target, absent colliding names, no competing producers/rules, stable configuration/processes through the whole run, observation and export, and fresh unpredictable run identity. These are external owner-enforced preconditions, not authority established by a manifest or by equal before/after readbacks. A change/use/restore between readbacks cannot be detected by versionless audit records. Later runtime preflight must require both `authoritative === false` and `dispatch_enabled === false`; a combined false dispatch signal is insufficient. It must revalidate target settings, installed profile/rule bytes, reload results and observations. Audit-only correlation does not suppress ordinary alert notifications. Use controlled lab destinations/History only, with no real provider tests. No capability is fabricated here.

The authored description is lowercase to preserve its effective receiver hash through the real Mapping loader/ORM normalization; the composed offline test verifies that contract. The profile selects six normal labels explicitly and requires nonblank values, plus explicit initial `startsAt` and `endsAt`. It discards all other incoming labels/annotations and uses no nested Mapping. It does not grant feed ownership. Scenario input has fifteen unique initial firing identities: threshold-five positive, four-input negative, two isolated groups of three. One initial start is captured for all inputs; validity is 600 seconds. The scenario budgets are finite test budgets, not throughput or capacity guidance. Expected `parent_emitted` is an audit decision; dispatch-disabled audit is not delivered parent proof. There is no clear, refire, restart, fault, enhanced-admission, or other-pattern claim. Sources remain DIRTY until independently owned target teardown; automatic source clear is absent.

`manifest.json` is a closed v1 transport schema, canonical UTF-8 JSON with sorted keys, compact separators, no ASCII/HTML escaping, exactly one trailing LF, integers limited to ±(2^53−1), and no floats. `manifest.sha256` contains lowercase SHA256 hex plus LF over those exact bytes. Artifact descriptors are sorted by exact fixed basename, exact positive byte size and SHA256. Unknown/duplicate JSON keys, extra/missing files, symlinks, special files and files over 1 MiB are refused. `hash-vectors.json` contains literal UTF-8 hex and SHA256 vectors for later Go parity; Go must disable HTML escaping and match Unicode encoding/newline. Profile effective hash uses the backend compiler's distinct canonical format, not this outer encoding. Manifest hashes prove byte integrity, not target readiness, source ownership, installed authenticity or runtime proof.

Later implementation must package target credentials, TLS/CA trust, deployment inventory, version and permission checks as external preconditions rather than embedding secrets or endpoints. Collision, partial import, stale runtime and unsupported readiness must refuse before stimulus. This offline slice performs no installation and does not exercise those checks.

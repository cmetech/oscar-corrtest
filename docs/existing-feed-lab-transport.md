# Existing-feed owned-lab transport seam

`NewExistingFeedLabInput` consumes the [frozen fixture manifest](existing-feed-manifest.md) and sends its finite firing inputs through the existing OSCAR HTTP client. This is a local transport prerequisite, not an integrated CorrTest runner or CLI route. It has no clear operation.

The constructor requires a separate receiver `domain.Target` with an explicit credential reference, `public-v1` for existing transport construction, and ID/origin exactly matching the frozen manifest. It revalidates the manifest and existing TLS/credential metadata, resolves the existing credential reference, and refuses empty credentials, ordinary bindings, input-route overrides and injected HTTP clients. The public API target and fixed `corrtest_ordinary_v1` binding validation are unchanged. The existing client supplies credential handling, custom-CA/insecure policy, timeout, bounded response reads and sanitized transport errors. No new credential mechanism or target flags are added.

The caller must independently establish an owned disposable lab, install the pinned top-level registry and read-only nested Mapping snapshot, and bind this receiver to that lab. A matching caller-supplied manifest or top-level HTTP acknowledgment cannot prove these conditions. This API must not execute against mutable production Mapping deployments.

`SendRecorded(ctx, index, recorder)` prepares the frozen fixture, checks its body limit and context, and calls `ExistingFeedRecorder` with the **entire** `ExistingFeedRequestEvidence`. The recorder must durably commit that evidence before returning success. A recorder error or absent recorder prevents send. Cancellation is checked again after recording. The recorded body bytes are sent with the frozen Host/User-Agent/If-Match and the independently configured receiver credential. Request bodies are capped at 1 MiB; shared response handling retains its 4 MiB cap.

After successful recording the instance retains the fixture as attempted, including cancellation before POST, response ambiguity and rejection. Further calls for that fixture are refused, including concurrent calls. This map is in memory only. A new instance does not know prior attempts: a future runner must reject persisted `(cohort, profile, fixture index)` attempts on reopen and retain UNKNOWN/DIRTY responsibility. This is not an exactly-once sender or durable idempotency protocol.

The client refuses redirects and has no application retry loop. Prepared requests clear `GetBody` and set no idempotency headers, so standard `net/http` cannot replay a non-idempotent POST body after a connection failure. This does not prove receiver completion or exclude transport work before bytes are transmitted. Timeout, connection loss or a failed response cannot authorize a fresh instance/retry.

Only HTTP 200 with `{"status":"ok"}` and exactly one matching `X-Oscar-Profile-Revision` header is `forwarded`. HTTP 200 `acl_denied` is `rejected`. Missing/wrong/multiple acknowledgment headers, malformed responses and other success statuses remain `indeterminate`. Redirects, non-success HTTP responses, timeout, connection loss and oversized responses return an error with an indeterminate result. Even forwarded means only acknowledged receiver forwarding under the external lab preconditions; it is not a nested-Mapping acknowledgment or Native/History completion.

The sole shared-client change delegates existing `doBytesWithHeaders` calls through a private helper. Existing callers pass no overrides. Only the new owned-lab transport supplies the frozen Host/User-Agent and disables request body replay. Existing ordinary and direct recorded-injection tests continue to pass.

## Local evidence

The initial behavioral RED run used an unimplemented sender and permissive constructor: both profile sends, recorder invocation, response classification and receiver-binding controls failed as expected. The first GREEN attempt exposed a test-fixture hang: its timeout handler waited for cancellation without draining the POST body. That test process was terminated after `httptest.Server` reported an active connection at close. Draining the body before waiting fixed the fixture; no production code changed for that correction. The original interruption is documented here and in the retained observed-output note rather than presented as an archived original log.

Focused tests exercise exact bytes/full evidence-before-send, credential separation, frozen headers, non-replayable request construction, recorder failure, pre/post-record cancellation, concurrent duplicate attempts, custom CA TLS, receiver binding, wrong/absent/multiple acknowledgment headers, malformed JSON, HTTP 202, 302/307/308 redirects, timeout, connection loss, HTTP 412, ACL denial and oversized responses.

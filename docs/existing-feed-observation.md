# Owned existing-feed observation prerequisite

`ExistingFeedManifest.VerifyHistory` checks one scoped firing History row against a separately verified original Native episode. Original labels and exact start must agree, allowing the shipped promotion of alertname and severity into History fields. Extra enrichment labels are allowed. Native `am_fingerprint` must equal the original 16-hex Native fingerprint; `oscar_fingerprint` must equal the separate nonempty top-level History fingerprint. Missing, ambiguous or changed identity fails closed. A successful public History GET is not a delivery receipt or semantic task-success proof.

`NewExistingFeedNativeObserver` uses the shared OSCAR transport's credential resolution, TLS policy, timeout and bounded response reader. Its private wrapper uses the qualified Native lab's fixed `publisher` Basic-auth account and permits only GET `/api/v2/alerts`. It adds the exact finite fixture's normal `node` or `hostname` filter. No reserved test labels are introduced. The observer refuses redirects, custom HTTP clients, path/query/userinfo origins and ordinary mutation bindings. It requires explicit target identity and a nonempty credential. Independent target/registry ownership and actual immutable Mapping installation remain external trusted lab preconditions; neither IDs nor caller-supplied snapshot hashes prove authority.

`Observe` returns exactly one full labels/start/fingerprint identity or an error. Only an actual empty JSON array yields `ErrExistingFeedNativeNotObserved`, which a future bounded read-only poll may retry. Null, malformed, oversized, foreign and duplicate observations fail closed. Read-only polling never permits resending input. This adapter has no POST, resolve, source-clear or cleanup operation.

This checkpoint adds identity/transport prerequisites only. The SQLite recorder and actual input transport are not yet connected to a user CLI or Runner. A subsequent finite owned-lab runner must freeze receiver, Native and History bindings, retain observations, and consume durable record-before-send and outcome methods. It must preserve UNKNOWN after uncertain transport/process interruption and retain unresolved responsibility after known forwarding. Generic reserved-label discovery and source-resolution cleanup must not be reused. The independently qualified backend cohort still provides its separate SQL delivery/task/window gates; these local tests do not extend that qualification to the new observer.

## Verification

Tests-first History and Native adapter controls initially failed against unimplemented stubs. A later explicit null-response control failed because null was incorrectly treated as an empty observation; requiring a non-nil decoded array corrected it. Retained [logs and hashes](qualification/20261017/existing-feed-observation/logs.json) preserve all three RED runs and the final evidence.

Focused controls cover both pinned profiles, full original identity, distinct fingerprints, promoted severity, no HTTP on invalid fixture, exact GET/filter/Basic auth, zero redirect follow-up, malformed/oversized/ambiguous responses, timeout, unsafe target bindings, default TLS rejection and explicit trusted-CA success. The focused race run passed 58 tests/subtests. The full suite passed 1114 tests/subtests across 27 packages with zero failures; the existing explicit owned-cohort and real Redis controls skipped, and two command packages had no tests. No Docker, external lab or backend source changes were made. Four source hashes are frozen in [the review manifest](qualification/20261017/existing-feed-observation/source-hashes.json).

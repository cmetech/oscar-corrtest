## Blockers to resolve before a joined run

1. **Actual receiver listener:** the private W16 helper needs an owned, bounded listener for real CLI HTTP. Keep the fixed registry/auth fixtures explicitly declared: this would prove packaged receiver processing and native transport, not production registry/auth availability. Do not expose selected-source handlers or the ordinary-array front ingress, which rejects CorrTest's identity labels.
2. **Rule mutation authority:** `managed_mysql_restore.py` `_APPLICATION_WRITES['correlator']` excludes `CorrelationRules`; it grants SELECT plus the controlled disable procedure. Real create/delete will fail. Correlator `routers/rules.py` also advances the writer revision when enabled. A reviewed, separately owned disposable writer configuration is required; do not silently widen the current cohort or seed rules and call that successful CorrTest ownership.
3. **Public API reachability/auth scope:** middleware listens only inside the cohort network; the host-facing native front is not a public API proxy. Run the CLI inside an owned network context (or explicitly manage a narrow TLS listener) and provide a temporary SQLite data directory/CA/credential references. The existing managed ordinary bootstrap sets `ENABLE_API_KEY_VALIDATION=false`; even if CorrTest sends a key, public auth enforcement is unqualified. Receiver fixture auth is a separate explicit seam.
4. **History wire shape:** actual History promotes severity to a top-level field and omits it from `labels`; CorrTest `eb557c3` retains only top-level alertname. Its ordinary probe sends `severity=warning` and requires every original label, so actual read-back would stop it and leave cleanup DIRTY. Fix by retaining observed severity separately and checking correspondence without manufacturing native labels. Missing, conflicting or changed evidence must remain unsafe to clear.
5. **Timing/configuration:** use an ordinary publication-enabled worker with Correlator dispatch and enhanced admission disabled. Record actual rule load responses and native callback timing rather than claiming readiness from CLI mode selection. The existing 600s fixture binding covers maxDuration4m +60s probe +30s cleanup; it does not justify arbitrarily slow callback routing.

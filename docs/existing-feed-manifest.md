# Frozen existing-feed fixture manifest

`internal/oscar/existing_feed.go` provides a preparation prerequisite for the finite owned-lab Splunk and middleware ordinary/window firing fixtures. It is not an executable CorrTest feed adapter: the runner, CLI, transport, History queries and cleanup remain unchanged. Real sender payloads need not be controllable, and this API does not accept arbitrary sender payloads.

## Contract

`FreezeExistingFeedManifest(spec)` validates a credential-free HTTP(S) receiver origin, target identity, a 32-character lowercase hexadecimal cohort ID, explicit positive whole-second UTC start, the qualified profile revision, and the complete nested Mapping fixture snapshot. `Mapping.Source` names the backend repository-relative fixture path; `Mapping.BodyBase64` retains the exact bytes; `Mapping.SHA256` must match both those bytes and the allowlisted fixture digest. Snapshot bytes are bounded at 1 MiB. No live Mapping fetch or profile discovery occurs.

The returned manifest stores values privately. Save the serializable `ExistingFeedManifestSpec` and revalidate it on reopen. A copied spec or prepared output cannot mutate a frozen manifest. A caller-supplied cohort ID, origin or digest does **not** prove ownership, receiver configuration or immutability of a deployed Mapping database. Execution must remain restricted to an independently owned lab with the same read-only Mapping fixture mounted and frozen registry used by the backend qualification. A top-level profile acknowledgment cannot establish this precondition.

The snapshot sources are `oscar/tests/oscar-webhookreceiver/fixtures/splunk/baseline.json` and `oscar/tests/oscar-webhookreceiver/fixtures/middleware_custom_alert/EXT_CUSTOM_ALERTS.json`. Byte-identical test copies are in `internal/oscar/testdata/existing_feed/`. Splunk uses both `splunk_alert_baseline/baseline` and `default/webhook_alerts` from its snapshot. Middleware uses `EXT_CUSTOM_ALERTS/alternate`; the complete original snapshot is retained rather than an unqualified subset. Top-level revisions derive from the shipped `oscar-conf/conf/mappings/webhook-profiles.json`, using the backend compiler's sorted description/elements serialization. The [backend qualification](../../oscar/docs/qualification/20261014/existing-webhook-window/README.md) records the independent executed expectations and fixture provenance.

`manifest.Prepare(index)` accepts only indices 0–5. The first five are `OrdinaryWindowProof`; the last is `OrdinaryWindowNoMatch`. Each uses host identity `owned-existing-<cohortId>-<index>`, ordinary `node` or `hostname` labels, and `NYC-<profile>` site. No reserved run labels are added or assumed to survive.

Each preparation returns independent exact JSON bytes and `ExistingFeedRequestEvidence`: the validated manifest, fixture index, existing `InjectionRequestEvidence` body bytes/base64/SHA-256/target fields, quoted top-level `If-Match`, and independently modeled full Native labels/start time. Endpoint paths are derived from the two allowed profiles; an arbitrary profile URL is not accepted. Repeated preparation is deterministic, but is not permission to repeat a POST.

Normalization inputs are explicit: `UserAgent` is `owned-existing-feed/1`, `RequestHost` is `owned-receiver`, and `StartsAt` is whole-second UTC. A future HTTP sender must use the recorded User-Agent and request Host, independent of its connection origin, and preserve them through any proxy. Splunk's Host-dependent summary pruning affects the `summary_copy` identity label; its explicit epoch `_time` prevents receiver-time fallback. Middleware's explicit timestamp is serialized with `+00:00`, retained verbatim as a label, and parsed for the Native start; `hostname` supplies its instance without client-IP fallback. Receiver-generated validity/end times are not modeled or claimed.

`manifest.VerifyNative(index, rows)` requires exactly one observation with the complete expected labels, matching start instant, and a lowercase 16-hex Native fingerprint. Missing/duplicate rows, extra/missing/changed labels, wrong fixture, wrong start and malformed fingerprint fail closed. Supply actual Native observations, not enriched History rows. This is a normalized-identity check only: it does not establish a trusted observation source, preserve the first fingerprint across later reads, prove an exact source episode, or authorize clear.

## Verification and limits

Tests were written first. Initial missing-symbol build failure is retained separately from behavioral RED. With type declarations and unimplemented preparation, both profiles failed preparation; a permissive constructor made all 19 initial invalid-manifest controls fail. The later two Host controls failed against the implementation before Host validation was added. Focused tests now pass, including all 12 literal request/identity cases, defensive-copy behavior, serialization/revalidation, invalid manifests and Native observation refusal. Independent source checks recomputed both compiled profile hashes and confirmed byte-for-byte Mapping fixture parity.

The final local `go test ./... -count=1 -json` run passed **966 tests/subtests across 27 packages**, with zero failures. `TestThresholdRedisOracleThroughRealHTTPClient` retained its existing opt-in actual-Redis skip; `cmd/generate-scenario-schema` and `cmd/package-zip` had no test files. Logs and their raw/archive hashes are retained under [qualification/20261016/existing-feed-manifest](qualification/20261016/existing-feed-manifest/logs.json). No Docker, network qualification, production configuration, main branch, commit or push was performed for this slice.

The smallest next integration is an owned-cohort caller that supplies and independently verifies the frozen runtime fixtures, persists the entire preparation before send, then sends these exact bytes once with the recorded Host/User-Agent/If-Match and separate existing receiver credentials. It must refuse redirects/retries, require the existing successful profile acknowledgment, and retain ambiguous-attempt responsibility. Observation must use the existing-feed ordinary label scope and preserve original Native identity before any owned-lab disposal. Runner/History/audit/timeline consumers must be connected and tested before claiming CorrTest feed integration.

Neither profile has a qualified source-clear contract. This slice provides no cleanup/disposal authority, exact-clear/order/idempotency guarantee, production execution grant, enhanced admission, parent dispatch, capacity evidence or UAT acceptance. Missing identity or completion evidence must remain DIRTY/UNKNOWN in any later consumer; preparation alone cannot discharge an interrupted input.

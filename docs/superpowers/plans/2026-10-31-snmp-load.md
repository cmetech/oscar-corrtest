# SNMP load mode implementation plan

> Execute inline with the executing-plans skill; final fresh-context adversarial review.

Goal: extend CorrTest Run test with a bounded, repeatable SNMPv2c load mode, preserving the existing receiver smoke check.

Architecture: reuse Net-SNMP and the existing runtime run lifecycle/event ledger, target credentials, History adapter and CSRF-protected forms. Add a deterministic packet plan and four embedded vendor fixtures derived from snmp-migration. No migration-generated files, OSCAR mappings, rate policy, notifiers or production rules are changed by the utility.

## Contract

- UI: target, port, mixed/individual family, 1–25 packets/s, 10–600 second offer window, clear delay 1–120 seconds, drain observation 10–1800 seconds. Default 5/s, 60 seconds, 30-second clear delay, 300-second drain.
- Weighted problem families: Juniper DHCPv6 interface limit 40%, Juniper DHCP interface limit 30%, Juniper AAA server 20%, Juniper address pool threshold 10%. Explicit migrated OIDs, typed MIB varbinds, expected mapped identities, source hashes. No random unknown OIDs or invented clears.
- Deterministic mixed schedule: problem/repeat/eligible clear slots, plus paced tail clears after offers. Record offer/tail counts separately. Rate is nominal total local send invocations, not new alerts/s or a wire-arrival guarantee; scheduling tolerance is max(1 second, 5% elapsed). Repeats preserve the original identity and payload. Identity tokens derive from the full run ID; all bulk fixtures carry the full token in their mapped alert key.
- Persist the complete nonsecret plan before sending, and a prepared/result event around each local send. Community stays in one private temporary config per run, never argv, evidence or error output. Bound each subprocess. No automatic retry of ambiguous UDP outcomes.
- Preflight one lifecycle per selected family, with mapped firing and repeat-still-firing observed before clear and resolved readback, before the timed load. Stop before bulk traffic if a family is missing/mismapped. Preflight samples are separate from measured load.
- Never catch up overdue packets with an unbounded burst. Record achieved rate, scheduling lag, send duration, local failures and unattempted packets. Cancellation stops new problems and sends paced clears only for attempted owned problems; cancel/failure cannot PASS.
- Reconcile exact owned History identities, expected original severity, group/agent and resolved state; duplicates/missing rows remain explicit. History success does not prove receipt of each repeated UDP datagram, outbound notification success, receiver admission capacity or overall performance qualification.
- Keep unresolved cleanup UNKNOWN/DIRTY; generic correlation cleanup must not mark SNMP runs clean. Crash recovery preserves interrupted/unknown state; no blind packet replay.
- One load run at a time; use existing run serialization and refuse new load starts during shutdown.

## Tasks and tests

- [x] Fixture/plan slice: tests for mapping/MIB-derived identities, weights, repeats, matched clears, total pacing, bounds and immutable run ownership; implement typed fixtures and deterministic plan.
- [x] Execution slice: ledger-before-send, private credential file, subprocess deadlines, cancellation/tail cleanup, conservative History reconciliation; test with local fake OSCAR and sender plus actual loopback UDP decoding.
- [x] UI slice: separate form and POST route with CSRF and numeric validation, existing run details/report; preserve single-pair tests.
- [x] Full Go tests, race tests for changed runtime paths, source-fixture parity check and fresh adversarial review. Build/install CorrTest only after evidence. Site smoke is separate: the local service currently has only a Beast target and no configured SNMP credentials; do not send to that target. No sustained OSCAR burst in this implementation task.

## Review focus

Secret leakage; cross-run identity collisions; failed/slow sends misreported as capacity; cancellation/crash ambiguous outcomes; missing/reordered/duplicate History records; preflight mistaken for measured throughput; cleanup that falsely claims success; existing single-pair behavior.
